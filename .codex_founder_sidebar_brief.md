# Founder navigation redesign brief

## Objective
Upgrade the founder-side navigation drawer in the existing Flutter application into a polished, production-ready founder command center inspired by the supplied narrow dark sidebar screenshot. The result must feel premium, focused, and useful to startup founders while preserving every working route and behavior.

## Target audience
Startup founders using Go Experts to manage their company profile, fundraising, investors, documents, communication, finance, and account.

## Existing application and constraints
- Flutter 3 / Dart, Material 3, flutter_bloc, and go_router.
- Implement inside the real application, not as standalone HTML.
- Primary output file: `E:\bhanu\goexperts_portal_app\lib\core\widgets\app_drawer.dart`.
- Existing design sources: `lib/app/theme/app_theme.dart`, `lib/app/constants/app_colors.dart`, and `lib/app/constants/app_sizes.dart`.
- Preserve shared freelancer, client, and investor drawer behavior.
- Preserve all existing founder routes, unread badges, refresh/logout behavior, and navigation callbacks. Do not invent routes or dead destinations for labels shown only in the screenshot.
- Prefer limiting changes to `app_drawer.dart`; make a small supporting change only when clearly necessary.
- Keep drawer usable on narrow phones and with large text. Maintain at least 44 logical-pixel interactive row height where practical.

## Aesthetic direction
“Founder cockpit”: deep ink surfaces, crisp neutral typography, restrained Go Experts red used as a signal rather than decoration, and thin borders/layering for depth. It should feel more like a serious operating console than a generic Material drawer. Avoid noisy gradients, excessive pills, and cramped microtext.

## Content structure
1. Compact brand/header area.
2. Founder-only startup identity/health card using available authenticated user and dashboard data. Show avatar/initials, founder/startup identity, role, plan/status where data exists, and a clearly labeled completion/health progress treatment. Degrade gracefully when fields are absent.
3. Always-visible, compact founder navigation grouped around founder jobs:
   - Overview: Dashboard, Analytics & Reports, Notifications.
   - Startup: My Startup, Pitch Deck, Business Plan, Team Members, Hiring.
   - Fundraising: Investors, Funding.
   - Assets & Documents: Media & Documents.
   - Communication: Messages, Meetings.
   - Finance: Wallet, Subscriptions.
   - Account: Founder Profile, Settings, Security Center, Support.
4. Strong current-route state with a slim primary accent, tinted surface, and clear icon/text weight. Badges must remain legible.
5. Retain footer actions such as refresh/logout if present.

## Typography direction
Use the application theme typography. Create hierarchy through size, weight, spacing, and tracking: confident startup name, calm metadata, small but accessible uppercase section labels, and highly legible menu rows.

## Color direction
Use `context.colors`, `context.theme`, and `AppColors`; the drawer must respond correctly to light and dark themes. Primary red is for active state, progress, key badges, and small brand moments. Avoid new hard-coded neutral `Color(0x...)` values.

## Memorable detail
A compact “startup health” identity module that makes the founder immediately understand the company profile status and turns the drawer into an operating context, not just a menu.

## Image needs
No new image is needed. Reuse the authenticated avatar/logo if available and provide initials fallback.

- Run `flutter analyze` scoped appropriately or full analyze if practical.
- Report exact files changed and commands/results.
